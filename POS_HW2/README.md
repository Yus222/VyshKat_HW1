# ПОС — Преподавательская оценка студентов

Консольное приложение на C# (.NET 8) для учёта студентов, критериев оценивания и выставленных баллов.

## Возможности

- Добавление, просмотр, изменение и удаление студентов и критериев
- Выставление, изменение, просмотр и удаление оценок
- Проверка допустимого диапазона баллов и существования студента и критерия
- Расчёт итогового процента с учётом весов критериев
- Два режима расчёта: по всем критериям или только по оценённым
- Сохранение ведомости в JSON и экспорт итогов в CSV
- Демонстрационный сценарий, который не меняет основную ведомость

## Запуск

Нужен установленный .NET SDK с поддержкой .NET 8. Команды выполняются из папки, в которой находится `POS_HW2.sln`:

```bash
dotnet build POS_HW2.sln
dotnet run --project src/Pos.Console
```

Запуск автоматических проверок:

```bash
dotnet run --project tests/Pos.Tests
```

Это отдельная консольная программа с проверками без xUnit. Она выводит `OK` или `FAIL` для каждого сценария и завершает работу с ненулевым кодом, если какая-либо проверка не пройдена.

## Пример работы

После запуска появляется меню для управления студентами, критериями и оценками. Например:

1. Добавить студента «Иван Иванов».
2. Создать критерий «Контрольная»: максимум 10 баллов, вес 2.
3. Создать критерий «Домашняя работа»: максимум 10 баллов, вес 1.
4. Поставить студенту 8 и 10 баллов соответственно.
5. Выбрать расчёт по всем критериям. Получится `86,67%`.
6. Экспортировать ведомость в CSV через пункт `13`.
7. Попробовать поставить 12 баллов за контрольную: программа отклонит значение, превышающее максимум.

Пункт `14` запускает отдельную демонстрацию. В ней создаются два примера:

- Анна Сидорова — **94,00%**
- Иван Петров — **77,00%**

Демонстрационная ведомость экспортируется в `reports/demo.csv`. Основные данные при этом не изменяются. При обычной работе сведения хранятся в `data/pos.json`.

## DDD

В предметной области используются студенты, критерии оценивания, оценки, рубрикатор и итоговый результат.

`Student`, `Criterion` и `Evaluation` — **Entity**, то есть сущности с идентификаторами. `Score` — **Value Object** для значения балла. `Course` — **Aggregate Root**, который хранит студентов, критерии и оценки и контролирует правила их изменения.

Основные ограничения: балл не может быть отрицательным или превышать максимум; оценку нельзя поставить неизвестному студенту или по отсутствующему критерию; максимум критерия нельзя уменьшить ниже уже выставленного балла. При удалении студента или критерия удаляются связанные оценки.

`ICourseRepository` задаёт интерфейс хранения данных. `TotalCalculator` — **Domain Service**, который рассчитывает результат с учётом весов. Пропущенные оценки можно считать нулями либо не учитывать — в зависимости от выбранной стратегии.

Формула расчёта:

```text
Итог (%) = 100 × Σ(вес × балл / максимум) / Σ(учтённых весов)
```

При отсутствии учитываемых критериев итог равен нулю.

## Архитектура

Использована упрощённая **Ports & Adapters** с четырьмя слоями. `Domain` не зависит от консоли, форматов файлов и конкретного хранилища. `Application` описывает сценарии работы. `Infrastructure` реализует сохранение и экспорт, а `Console` принимает ввод пользователя.

Основные зависимости: `Console → Application → Domain`. Инфраструктурные реализации подключаются через интерфейсы, а регистрация зависимостей выполняется в `Program.cs` с помощью `Microsoft.Extensions.DependencyInjection`.

При изменении данных `PosFacade` сначала изменяет копию агрегата, затем сохраняет её. Если запись не удалась, текущие данные в памяти остаются прежними.

## Паттерны GoF

**Factory (порождающий)** — `EvaluationFactory`. Создаёт оценки с проверкой допустимого диапазона баллов.

**Facade (структурный)** — `PosFacade`. Объединяет действия приложения: управление студентами и критериями, выставление оценок, расчёт результата, экспорт и демонстрацию.

**Strategy (поведенческий)** — `AllCriteriaStrategy` и `GradedOnlyStrategy`. Позволяют выбирать способ учёта критериев без выставленных оценок при расчёте итога.

## Использование ИИ 

 Я разобрал требования к системе оценивания и определил, какие данные она должна хранить: студентов, критерии, выставленные оценки и итоговые результаты. На основе этих требований разделил проект на слои `Domain`, `Application`, `Infrastructure` и `Console`. В доменной части спроектировал классы `Student`, `Criterion`, `Evaluation` и `Score`, а также агрегат `Course`, через который выполняются изменения данных. В `Course.cs` реализовал добавление, редактирование и удаление студентов и критериев, выставление оценок, а также проверки существования нужного студента и критерия. Отдельно предусмотрел удаление связанных оценок при удалении студента или критерия и запрет на уменьшение максимального балла ниже уже выставленной оценки.

Самостоятельно реализовал расчёт результата в `TotalCalculator` с учётом веса каждого критерия. Для двух способов расчёта выделил `AllCriteriaStrategy` и `GradedOnlyStrategy`: в первом случае критерии без оценки учитываются как нулевые, во втором — исключаются из расчёта. `EvaluationFactory` использовал для создания оценок, а `PosFacade` — как общий интерфейс основных сценариев приложения. В консольной части написал меню для добавления студентов, создания критериев, выставления оценок, просмотра итогов и экспорта ведомости. Сохранение данных вынес в `JsonCourseRepository`, формирование таблицы — в `CsvReportExporter`.

ИИ  использовался как справочный инструмент для отдельных технических вопросов. В частности, я уточнял синтаксис сериализации через `System.Text.Json`, использование `JsonSerializerOptions` и обработку путей при записи JSON. При настройке `Program.cs` обращался за подсказками по регистрации `ICourseRepository`, `IReportExporter` и двух реализаций `IResultStrategy` в контейнере зависимостей. Также использовал объяснения по экранированию кавычек в CSV и форматированию десятичных чисел через `CultureInfo.InvariantCulture`. Эти консультации относились к использованию библиотек C#, а не к выбору предметной модели и общей архитектуры.

При проверке программы ИИ помогал придумывать дополнительные граничные случаи: отрицательные баллы, превышение максимума, обращение к несуществующему критерию и повторное изменение оценки. Сами проверки в `tests/Pos.Tests/Program.cs`, вычисление ожидаемых результатов и исправления в условном сценарии выполнялись мной. После этого я собрал проект И запустил автоматические проверки. Фактические результаты запуска приведены в разделе «Тестирование»: 16 ноября 2026 года сборка прошла успешно, все **19 из 19** проверок завершились без ошибок, демонстрационный сценарий трижды выдал **94,00%** и **77,00%** и создал CSV-файл.
